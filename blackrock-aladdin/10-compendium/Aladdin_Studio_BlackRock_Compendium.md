# Part 1. Aladdin

## 1.1 What Aladdin is

Aladdin is the investment platform BlackRock built for its own business and sells to other institutions. BlackRock's own wording, printed at the foot of its eFront pages: "Aladdin® is a technology platform used by asset managers and owners including banks, financial institutions, pensions, corporations, insurers, and wealth managers. The Aladdin platform unifies the investment management process, providing a common data language within an organization to enable scale, provide insights, and support business transformation." [page: eFront Insight LP video] The same text says "Aladdin® and eFront® platforms bring together public and private asset class data to create an industry-recognized whole portfolio solution for investment professionals globally." [page: eFront Investment Café video]

Brennan Rosales, AI engineering lead, at LangChain Interrupt 2025: "Aladdin is a proprietary technology platform that unifies the investment management process. It provides asset managers with a whole portfolio solution that gives them access to both public and private markets ... This system is built by the industry for the industry. BlackRock is the biggest user of Aladdin." [T1-16 LangChain Interrupt, 2025]

"Whole portfolio" is BlackRock's current product language. The Whole Portfolio page describes "a connected ecosystem that gives institutional investors an enterprise-wide view across all asset classes—including both direct and indirect investments in private markets" and "an integrated ibor that supports public and private assets"; its counters read "6 years delivering Whole Portfolio solutions—with 20+ years delivering solutions for private markets" and "50,000 unique private markets companies maintained and 2k+ private markets risk factors monitored daily". [page: Whole Portfolio] Tarek Chouman, Global Head of the Aladdin Client Business: "BlackRock and Aladdin was built for the concept of the whole portfolio." [T2-063 APAC Client Forum recap, 2025]

The investment book of record is the anchor. Kunal Khara, Global Head of Aladdin Product: "Our iBOR is comprehensive and consistent that allows all clients and all users to have a single source of data for their portfolio, for their positions, for their exporters." [T2-061 Best Overall Technology Provider 2023, interview 2024] Richard Newman, GM of Aladdin Studio: "It does start with IBOR." [T1-11 Never Done: Data, the key ingredient, Jan 2025] The specs model both books: AborLot records carry a parallel OBOR lot id so the accounting and investment books reconcile at lot level. [spec: AborLotAPI]

Users inside a client firm, as the transcripts name them: portfolio managers, traders, trading and data operators, compliance, risk, performance analysts, fund accountants and CFOs. Dave Woodhead, head of engineering for Aladdin Studio: "The portfolio manager is the tip of the iceberg. Behind them, you have an entire raft of data operators of of trading operators that make sure that the investment life cycle works as it's supposed to." [T1-01 Snowflake Data Cloud podcast with Woodhead, published 11 Nov 2025; auto-captions] Aladdin Accounting: "Our clients are CFOs, they're controllers, they're heads of performance". [T1-33 Big Little Questions: Accounting] The UserAPI classifies accounts as a client employee, "A User who is an employee of a AladdinProvider", a system user, or a BlackRock employee. [spec: UserAPI]

## 1.2 Where it came from

Woodhead dates the platform at "just over 20 years": "As as BlackRock grew, our clients recognized that our technology was differentiated and asked could they use the same software. So BlackRock pretty quickly entered the fintech business and we started offering Aladdin as a service." [T1-01 Snowflake Data Cloud podcast with Woodhead, published 11 Nov 2025; auto-captions] Randy Fradin: "A Latin was created, you know, 30 years ago. And in that time, we've demonstrated repeatedly our ability to kind of completely re-underwrite the stack of technology and capabilities underpinning a Latin. I think our ability to do that without disrupting customers is kind of our superpower." [T1-28 Big Little Questions: Fradin and Kerner, undated]

The engineering history is told in the Principles of Design podcast with Sue Zheng, Tech Fellow, and Afwa Kandawire, Global Head of Aladdin Platforms (May 2023). Zheng: "one of the engineering ethos we always had was one database. You join, people tell you it's one database, you cannot create another database. But at some point ... you realize there's a physical constraint to one database. So, then we evolved one database to one source of truth". The first break was in trading: "we probably have to take parts of the order management or order execution system and put it on top of a different real time transactional database ... at that point we leveraged Cassandra. So, before that everything was in one database, a side base database." ("Side base" is the transcript's rendering of Sybase.) The technique was "writing behind, so that yes, we're going to be in a separate database so that we can reduce the contagion risk, but also making sure everyone still has access to the same information". [T2-027 Principles of Design, May 2023] On Charlie Hallac: "He would check every database change ... If you're going to write to this, make sure there's only one application writing to it ... The service was just called a BMS service back then". She also recalls "rebuilding an old C++ application into Java". [T2-027]

Kandawire on the present: "we've started to migrate away from our layered architecture to a services architecture ... Every single client environment looks the same, is built the same way, we have a single control plane and a single source of truth ... one of the things that we're starting to introduce is this notion of domain driven design and the idea being that the database is no longer the single source of truth, but rather the domain is the single source of truth for that domain." [T2-027] On same code: Zheng, "in Aladdin we always try to push the same software out to all clients ... I don't want to be on the hook for saying I have like 50 different versions out there"; Kandawire, "That notion of a single code base at all clients leads to simplicity, it's what enables the scale, it's what enables the reliability." [T2-027]

Cloud. Kandawire: "I joined at a point in time where we had made a decision on how we were going to migrate to the cloud. We had chosen our cloud provider ... the first stage would be a lift and shift ... the principal reason for doing a lift and shift was to ensure that we could actually enable Aladdin to be available to more prospects in more regions than we had datacentres available." [T2-027] Microsoft's Ignite recap (Dec 2024): "Five years ago, we began working on a strategy to move them into the cloud on Microsoft Azure. Today, all BlackRock's technology platform clients and services are hosted in the Azure cloud". [page: Microsoft Cloud blog, Dec 2024] Lance Braunstein, head of Aladdin Engineering, March 2023: "you're great at data centers. We will never be the data center operator that you are, and that's fine. So, we have partnered with you." [T2-022 Microsoft partner story, Mar 2023] The Studio briefing records a client-by-client migration with Microsoft Treasury first, and a December 2025 AWS partnership, "cloud-agnostic by design", with AWS-hosted availability expected H2 2026. [briefing: Studio]

Private markets. Sudhir Nair, Global Head of Aladdin: "Aladdin grew up very much as a public markets oriented technology. And it wasn't until 2019, when we did our first major technology acquisition with E-Front, that we had the opportunity to bring side by side through this concept of the whole portfolio, the public markets investment technology alongside private markets investment technology." In the same episode: "about three months ago, we closed our next acquisition", Preqin. [T2-033 Never Done: Sudhir Nair, Jun 2025]

## 1.3 What it does: the investment lifecycle it covers

Lou Rosato, BlackRock operations, at Symphony Innovate 2026: "We have a technology called Aladdin. That's our proprietary workflow. It goes end-to-end from risk to investment to trading to post-trade to accounting all the way through the life cycle." [T1-10 Symphony Innovate 2026] Khara: "the front middle and back office all managed through Aladdin." [T2-061] Aladdin Accounting: "you can go from that first order through the trade, through all the operation protocols into accounting without lifting up the pencil". [T1-33]

The 54 public specs sit in eleven domains: accounting, analytics, clients, compliance, data, investment-operations, investment-research, platform, portfolio, portfolio-management and trading. [briefing: suite architecture] Pre-trade compliance is a property of the order: posting takes `whatIf` ("True to post orders in a what-if mode") and `runCompliance` ("Default is true to run compliance on this post order request") and returns violations inline. [spec: OrderAPI v1] Compliance rules have ten types (prohibition, concentration, value at risk, disclosure, scripted, look-through definition, information, trade, counterparty, counterparty exposure limit) with overnight and intraday flags. [spec: ComplianceRuleAPI] The cash ladder projects cash by settlement date and currency, optionally including intraday trades, open orders, estimated new cash, collateral and unfunded commitments. [spec: CashLadderAPI v2] Operations APIs cover corporate actions, coupon resets, MBS factors, cash transmissions, collateral statements and broker and settlement reference data; the accounting domain describes itself as "Aladdin Accounting". [briefing: suite architecture] [spec: PortfolioConfigurationAPI]

Performance and reporting run through Explore. A client training recording: "performance analysts primarily leverage explore a One-Stop shop for reporting and portfolio analysis"; returns "are calculated at the security level and aggregated to the sector portfolio and Enterprise levels daily", decomposed into price, income, pay down, FX and trade P&L, with "a Brinson 2 or three Factor attribution analysis". [T1-06 Fixed Income Performance Analyst, undated] The Explore classroom recording shows a web application launched "through your genie toolbar" or by adding "/app/Explorer" to the client site URL, with workspaces, widgets, risk settings ("analytical var as a 95% instead of an 84%"), stress P&L columns and saved what-if portfolios; the risk tab is "pulling straight from PRT". [T1-09 Aladdin Explore Intro, undated] A BlackRock webinar calls Explore "One of the main kind of all flagship tools ... our portfolio analysis and reporting application." [T2-048 Assessing the impact of escalating trade tensions, spring 2025; Whisper]

## 1.5 How it is built and run

Organisation, per Rosales in 2025: "we also sell and support hundreds of clients globally across 70 countries ... The Aladdin organization is made up of around 7,000 people, with over 4,000 of those being engineers. And these engineers build and maintain the around 100 Aladdin front-end applications that thousands of people use every day." There are "say, 50, 60 Aladdin engineering teams that cover specific domains". [T1-16 LangChain Interrupt, 2025] Kandawire's platform group runs "product families": mission control (keeping Aladdin up, maintenance "with a cadence and in a highly controlled way"), hosting services, engineering services, enterprise architecture and a product office. [T2-027]

Tenancy. "Every single client environment looks the same, is built the same way, we have a single control plane and a single source of truth." [T2-027] The specs carry the tenant throughout: `clientAbbreviation` on ADC datasets, `accountCode` on external trade references, a per-client ADC database, reconciliation against a gold-copy client, OAuth endpoints at client.blackrock.com. [spec: AdcDatasetAPI] [spec: TradeAPI v2] [briefing: suite architecture]

Hosting. Azure after the lift-and-shift in 1.2; all clients on Azure as of December 2024, with "New rollouts now take weeks instead of quarters to complete" and data "encrypted at rest and in transit". [page: Microsoft Cloud blog, Dec 2024] Fradin: "Initial step of moving the Latin into Azure was always meant to be the springboard to what comes next, which is essentially a perpetual cloud journey." Microsoft's Matthew Kerner notes Aladdin is "co-located" with "the Azure OpenAI integration". [T1-28] AWS: announced December 2025, availability expected H2 2026. [briefing: Studio] Khara: "a lot is built on a very, very scalable cloud-based infrastructure and architecture to handle the heightened volume, as well as the variety and the velocity of data and transactions". [T2-061] An Aladdin Container Platform on Kubernetes with a Go control plane appears only in job postings; the specs are hosting-neutral. [briefing: Studio] [briefing: suite architecture]

Conventions the specifications show:

- Protobuf and gRPC underneath, REST on top: every spec carries `rpcStatus` (google.rpc.Status), `Any`, `google.type.DateTime`, `updateMask`, `pageToken`, `LongrunningOperation`, enums named `FOO_UNSPECIFIED` and messages such as `v1FilterOrdersRequest`, the fingerprint of gRPC-gateway transcoding. "Aladdin Graph" names the layer; specs cite naming "agreed with Aladdin Graph team". [briefing: suite architecture] [spec: OrderAPI v1]
- Google API design rules enforced by a linter, with suppressions such as `api-linter: aladdin::9016::query-custom-method-http=disabled aip.dev/not-precedent` justified by "changing existing URI to suggested URI will break all citizen developers code". [spec: RiskRuleAPI]
- Stability labels: 24 alpha, 6 beta, 23 stable, 1 sunset; 190 of 301 operations POST; 35 long-running. [briefing: suite architecture]
- Bitemporal fields: `validBeginDate`, `validEndDate`, `entryTime`, `expiryTime` on risk exceptions and metrics; a `bitemporal` property on ADC datasets. [spec: RiskExceptionAPI] [spec: AdcDatasetAPI]
- Four-eyes approval: ADC dataset states DRAFT, REVIEW ("ready for a 4-eyes check prior to release"), APPROVED, REJECTED; `resolutionRequiresFourEyesApproval` on rule assignments; `confirmedBy` and `reviewedBy` on cash transmissions. [spec: AdcDatasetAPI] [spec: ComplianceRuleAssignmentAPI] [spec: MiscellaneousCashflowAPI]
- Order compliance timing: `complianceTimeout` is "specified in seconds (example format: "10s") ... If the non-zero time is reached and the run is not complete, orders will be posted with the "Compl Pending" status set regardless of any violations". Trades carry `compliancePending`. [spec: OrderAPI v1] [spec: TradeAPI v2]
- Two-layer authorisation: an application key header `VND.com.blackrock.API-Key` plus OAuth 2.0 (scopes such as `trading.order_management.order.v1.Order:read`), a client key or basic auth at the gateway; inside, permission codes `brkrMaint` (brokers), `asReAsMOD` (restricted assets), `PortGroupMOD`, `asPortMOD`, `GPMaint` (portfolio groups), `PERMS_GROUP_MOD_perm` or `MOD_PERMS` (permissions), and the newcash set `VIEW_NEWCASH, CASH_PAY, CASH_MOD, CASH_CONF, ASSET_MOD, ASSET_CONF, CASH_TRANSFER, ASSET_TRANSFER`. The user and permission APIs state "This is not intended to be used for Authorization." [spec: BrokerAPI] [spec: RestrictedAssetAPI] [spec: PortfolioGroupAPI] [spec: UserGroupPermissionAPI] [spec: EnrichedCapitalFlowAPI] [spec: PermissionAPI]
- Internal expression languages: `bqlExpression`, `bqlFilter`, `jql` on trade routing. [briefing: suite architecture]

## 1.6 Risk and analytics

Woodhead: "at our roots where we started, our differentiation was our ability to understand the risk of the market. That's what we call our analytics factory ... We called it the green package ... because it was printed on green paper ... That's my portfolio risk for the day." Start-of-day risk "is still the heart of our of our data ecosystem. It's the most valuable product that comes out of our analytics factory." [T1-01] The Green Package persists in the specs as a portfolio attribute ("risk services/green package are part of Client Services") and a compliance disaggregation option. [spec: PortfolioToolkitAPI] [spec: ComplianceRuleAPI]

Factor counts in the corpus: "2k+ private markets risk factors monitored daily" [page: Whole Portfolio]; "a 3,000 risk factor model" (Aladdin Wealth) [T1-08]; "my 2500 plus factors" in the Explore stress demo, with "factor models across our alternatives and our public assets" [T2-048 Assessing the impact of escalating trade tensions, spring 2025; Whisper]. The fact-check attributes "monitors over 5,000 risk factors daily" to the Fivetran write-up, but the Fivetran blog text in the pulls does not contain that phrase. [page: Fivetran blog]

Scenarios: BlackRock calls them Market-Driven Scenarios, "MDS", and RQA, its risk management group, uses them: "we are using scenarios every day at the moment." Rory Van Swannenberg, EMEA head of sustainability and platform risk in RQA, describes the construction: a hypothetical event; "policy variable" shocks that are the key drivers ("What Aladdin is going to do is take those policy variables and propagate those shocks throughout the rest of the market. It's how you get that bottom up full portfolio approach"); a plausibility check ("if I put shock A on equities and shock B on interest rates is that likely or unlikely"); implied shocks ("Use the risk model and covariance matrix to imply shocks on all of the other underlying factors"); then portfolio analysis. Each scenario carries a rationale, catalysts and a calibration ("as much art as it is science"). The worked example, built "from March 6" 2025, is "US-Europe decoupling": a VIX shock, the S&P "outperforming MSCI Europe by 5%", a "big divergence" between the German and Treasury 10-year yields, with the catalyst "Germany revising its debt" brake, and an EMEA aerospace and defence factor receiving "a large shock". Stress testing "is done through a bottoms up portfolio modeling approach and that allows you to have an integrated view of your exposures down to the asset and fund level across both public and private." In Explore, BlackRock gives clients "a stress scenario as a basis or as a viewpoint"; users "can add multiple scenarios where you can also just edit these scenarios shocks", set "the kind of implied frequency" and "what the magnitude is according to my own viewpoint", copy an existing scenario "as a new scenario for yourself", choose a risk model and long- or short-term settings; the demo uses "the US euro decoupling scenario". [T2-048 Assessing the impact of escalating trade tensions, spring 2025; Whisper] Whole Portfolio lists "proprietary risk models, stress testing tools, pacing analysis, and real-time analytics". [page: Whole Portfolio] Yulia Yudelevich and Michael Sternberg: "what we try to do with our risk models is to translate data into actionable information ... There are a lot of new forms of data, unstructured data, news events ... And we need to bring that into our analytics and make that available to people, but with caveats." [T1-22 Big Little Questions: Analytics and risk, 2024]

Climate. Aladdin Climate's models "are really based on four core steps ... plus one if we can see their private markets": scenario definition from NGFS and IPCC, translation "into microeconomic impacts for us to be able to restate the entire balance sheet of the companies in our covered universe", a bottom-up company restatement, and "an updated free cash flow to equity that then flows into the Aladdin traditional asset evaluation models"; for equity this is "a dividend discount cash flow model with the climate adjusted cash flows", and "we don't do a stochastic modeling". Private securities get "a waterfall approach ... starting from a recording of public securities that are in the same geography or in the same subsector"; real assets are modelled "on the longitude and latitude where they are located" by peril. Targets counted are "SPTI targets, so science verified targets or CDP targets" (SBTi, as Whisper renders it), and projections are shown by scope and by "EVIC intensity or revenue intensity". In the Explore demonstration on MSCI ACWI against the S&P 500, physical and transition coverage is "both 99.9%" and the combined adjustment "a 9.3% downward adjustment on the current value". [T2-047 An introduction to Aladdin Climate, 2024 (file name); Whisper]

Risk governance in the specs is separate from compliance: RiskRule (metric, limit, breakdown; absolute limits such as 250 bps tracking error or relative), EvaluatorAnalytics (metric source "Aladdin Analytics" or custom data), RiskCustomEvaluationMetric, RiskException, RiskWorkflow and RiskConfig driving "the Risk Radar UI". Analytics reaches clients as data retrieval and rule evaluation, not a calculation engine. [briefing: suite architecture] Newman, Jan 2025: "we have these engines that historically were run through interfaces. So we're providing those APIs now. We're releasing soon the ability to actually access those analytic APIs, portfolio analysis, security analysis, things like that. That's all part of the Studio umbrella." **Request conventions.** The specs follow Google's API design conventions: resources with custom methods such as `:filter`, `:batchCreate`, `:batchValidate`, `:search`, `:undelete`, `:listRevisions` and `:cancel`; AIP-160 style filter strings; `pageToken` pagination; `updateMask`; `rpcStatus` (google.rpc.Status) and `Any` types; enums named `FOO_UNSPECIFIED` [briefing: suite architecture]. POST is 190 of the 301 operations, and filtering is done by POST with a criteria body rather than GET query strings; batch endpoints are capped at 100 per request for broker reference data, 1,000 for restricted assets and 10,000 rows per page [briefing: suite architecture]. Ten specs expose a `GET /longrunningoperations/{id}` endpoint and 35 operations are flagged `x-aladdin-lro`; the SDK polls these [apis.json; briefing: suite architecture; SDK README]. Many entities carry entry and expiry times or valid-begin and valid-end dates, a bitemporal pattern that supports as-was reporting [briefing: suite architecture]. "Four-eyes" approval appears by name on compliance rule assignments and ADC dataset review; cash transmissions need a confirmer and a reviewer, and risk rules carry sign-off authors [briefing: suite architecture; spec: MiscellaneousCashflowAPI].

The Order API's `v1PostOrderConfig` carries `whatIf`, `runCompliance`, `accountCode`, `externalEntityType` and `complianceTimeout` [spec: OrderAPI, digest]. Posting an order returns compliance violations inline, so pre-trade compliance is a property of the order API [briefing: suite architecture]. The candidate's V8 document, whose add-on figures were recomputed and matched, records `runCompliance` defaulting to true and an order status of "Compl Pending" while compliance runs [V8, OrderAPI definition file]. The Portfolio entity in PortfolioToolkit has 850 properties, with "slices" that expose subsets [spec: PortfolioToolkitAPI, `v1Portfolio | props(850)`]. Fields named `bqlExpression`, `bqlFilter` and `skipBqlValidation`, and a comment "refer to BQL ord_flags", point to an internal query language used for filters and routing rules [briefing: suite architecture; spec: PortfolioToolkitAPI]. Every public spec is tagged `Access.Internal`; the meaning of the tag is not documented publicly [digest; briefing: suite architecture].

The specs carry inline linter suppressions such as `api-linter: aladdin::9016::query-custom-method-http=disabled aip.dev/not-precedent`, which shows BlackRock running Google's api-linter plus its own `aladdin::` rules with justified exceptions [briefing: suite architecture]. In the RiskRule and EvaluatorAnalytics APIs the justification reads: "We need to do this because it is an existing api changing existing URI to suggested URI will break all citizen developers code." [spec: RiskRuleAPI; spec: EvaluatorAnalyticsAPI]. The CashLadder v2 GET endpoint "is provided solely for backward compatibility and should no longer be used" [spec: CashLadderAPI].

**What each domain exposes.**

*analytics.* A risk-oversight suite surfaced in an application the specs call Risk Radar: RiskRule holds metric, limit and breakdown conditions with draft and approved states; EvaluatorAnalytics triggers evaluation of a portfolio against all or one rule as a long-running operation; RiskException and RiskWorkflow hold breaches and work items; RiskCustomEvaluationMetric lets a client upload its own metric values [apis.json; briefing: suite architecture]. Climate exposes "physical, transition, and temperature alignment analytics as of a given date", and EsgData "a centralized source of ESG data and meta data across multiple vendors" [spec: ClimateAPI; spec: EsgDataAPI].

*data.* SecurityCreation "is used to create CDS, CDX, Equity Equity, Equity Option, Futures, FX NDF, FX SPOT, FX FWRD, FX CSWAP, FX Option, Swap, Swaption, CASH/TD, CASH/REPO, ARM/TBA and MBS/TBA" securities, 15 operations [spec: SecurityCreationAPI].

*trading.* Order v1: "Filter, post or cancel orders. An order is a directive from a portfolio manager to the trading desk to execute a particular investment decision", with `:post`, `:cancel`, `:filter`, `:batchPost`, `:batchCancel` and an order-id filter [spec: OrderAPI]. Trade v2: "Post, cancel, filter and retrieve trade(s)", a BlockTrade with child allocations, broker quotes, settlement details and external trade references [spec: TradeAPI; briefing: suite architecture].

*compliance.* ComplianceRule ("used to automatically monitor whether a fund adheres to a regulation, client mandate, or internal guideline"), ComplianceRuleAssignment (binds rules to portfolios with four-eyes approval), Level (start-of-day and intraday room to limit) and Violation (breaches with contributing positions) [apis.json; briefing: suite architecture].

*portfolio_management.* CashLadder v2 gives "a settlement date based ladder of cash balances for all the exposure currencies for a given portfolio group and cash date"; Strategy names investment strategies that orders and trades are tagged with; CIDReader and CIDWriter load Custom Investment Datasets, where "CIDS does not transform the input data in any kind. The writer of the data owns it" [spec: CashLadderAPI; spec: CIDWriterAPI, via V8 S21].

*investment_research.* ResearchNote v2 (templated notes with permission groups), Engagement (meeting records), AnalystCoverage, Watchlist, and Criterion, stored screening expressions such as `((price > 55 OR oas = 75) AND market_cap < 1mm)` with alert schedules [apis.json; briefing: suite architecture].

*investment_operations.* CorporateAction and CorporateActionEntitlement (elections instructed to the custodian), CouponReset (from "Aladdin's Bulk Rate Mechanism (BRM) module or sourced from external vendors"), PrincipalInterestFactor, MiscellaneousCashflow (which sends money out "through the transmission framework" once confirmedBy and reviewedBy are recorded), CollateralStatement (from agreements set up in DECO), and the broker reference set: Broker, BrokerDesk, BrokerExternalAlias, BrokerConfirmRouting, CounterPartySettlementInstruction and its template, Contact, AccountInfo, Audit [apis.json; V8 S28].

*accounting.* "Aladdin Accounting" configuration attributes by process code, Valuations (NAV workflow with status, sign-off, publication time, Dietz and total return fields, and valuation exceptions with NAV impact), AborLot (lots "retrieved from the ledger_a_summary table" with a parallel OBOR lot id) and CompositeMembership [spec: PortfolioConfigurationAPI; spec: ValuationsAPI; spec: AborLotAPI].

*clients.* EnrichedCapitalFlow: "the cash and asset subscriptions coming into a fund and the cash and asset redemptions going out of a fund", with estimate and actual states, authorise and confirm actions, and permissions from a module called "newcash" such as CASH_PAY [spec: EnrichedCapitalFlowAPI; V8 S30].

*portfolio.* PortfolioToolkit (retrieve, filter and search portfolios and slices), PortfolioGroup (a hierarchy with ancestor and descendant queries), RestrictedAsset ("used prevent assets from being traded in Aladdin") [apis.json].

*platform.* User, UserGroup, UserGroupMember, Permission and UserGroupPermission for administration, which the specs say are "not intended to be used for Authorization", plus AdcDataset, which "Manages Datasets in Aladdin Data Cloud (ADC). Used by Studio's ADC Admin Center." [apis.json; spec: AdcDatasetAPI].

## 2.4 Authentication and authorisation

Every API request carries an application key header, `VND.com.blackrock.API-Key`, for an application registered in Studio, plus one of: OAuth 2.0 authorization code, OAuth 2.0 client credentials, an `X-API-Key` client key, or basic auth [briefing: suite architecture]. The OAuth endpoints are at `client.blackrock.com/api/oauth2/default/v1/` [briefing: suite architecture]. Scopes are per resource, for example `trading.order_management.order.v1.Order:read` and `trading.order_management.order.v1.Order:write` [briefing: suite architecture]. The SDK README says "Client ID and Secret can be sourced from Studio UI by creating a OAuth application under a Project", a basic-auth "API Token" is "registered via Studio UI", and selected scopes "must be a subset of scopes setup for the app in Studio UI" [SDK README].

Authorisation is two-layered. Underneath the OAuth scope, the specs still cite Aladdin permission codes that the calling user must hold, for example `brkrMaint`, `asReAsMOD`, `PortGroupMOD`, `PERMS_GROUP_MOD` and `VIEW_NEWCASH` [briefing: suite architecture]. The capital-flow API requires "standard API permissison ALADDIN_API_USER" and "standard newcash permissions" [V8 S29, S30]. Registering an ADC dataset "requires "StudioAdmin" Aladdin perm assigned to the user", and column refresh names the "StudioAdmin" Aladdin Permission Type and the "DATACLOUD" Aladdin Permission Group [V8 S23, AdcDatasetAPI definition file].

ADC authentication is separate from API authentication. The SDK's ADCClient uses "'oauth' or 'snowflake_jwt' (i.e. RSA Keys) authenticator types for snowflake connectors"; where "ADC OAuth is configured via Studio application, SDK's ADCClient will attempt to fetch an OAuth AccessToken from Aladdin's TokenAPI", on the assumption that the "User has authenticated with the ADC OAuth client application by logging into Aladdin Studio UI" [SDK README].

The User API names three user types: `USER_TYPE_CLIENT_EMPLOYEE` ("A User who is an employee of this client"), `USER_TYPE_PROVIDER` ("A User who is an employee of a AladdinProvider") and `USER_TYPE_SYSTEM`; its description lists "Aladdin Client's employees granted access to Aladdin", "BlackRock employees granted access to client's Aladdin products" and "bot accounts granted access to Aladdin" [spec: UserAPI]. The same description links to a developer guide at `apps/aladdin-developer-portal/#/guides/developer-guide` on the client's Aladdin site [spec: UserAPI].

## 2.6 Aladdin Data Cloud

ADC runs on Snowflake with Fivetran moving the data. "Fivetran allows us to take data from a single source and move that with low latency into a Snowflake landing zone, where we transform it using our enterprise data platform" [page: Fivetran blog, 28 Aug 2024, quoting Woodhead]. Users "can access their Investment Books of Record (IBOR), Accounting Books of Record (ABOR) holdings and other market data", and "users have access to dynamic tables for building Snowpark apps and asking cross-dimensional time-series questions" [page: Fivetran blog]. Fivetran "helps address three key issues: disaster recovery, data recoverability, and consolidation of previously siloed data sets", and the write-up records Woodhead's Snowflake Summit 2024 statement: "We expanded Aladdin® Data Cloud's data network capabilities, enabling clients to bring their own data into ADC, and to distribute Aladdin data to their own data ecosystems" [page: Fivetran blog].

Delivery is by Snowflake data sharing: clients get the data "sitting in their cloud provider of choice, they're sitting in their technology of choice through snowflake and through data sharing" [T1-01]. On scale: "We share data to hundreds of Snowflake accounts and we're managing hundreds of vendors, tens of thousands of pipelines", and "One of our biggest challenges is fleet management" [T1-01]. Pipelines are "moving away from batch oriented pipelines to more real time pipelines" using dynamic tables [T1-01]. Goel gives the latency: ADC is "a near real time data store ... which we think about as a data integration hub so that you can access all the data that you need in a lot in an e-front through one single source within 15 minutes of latency from various kinds of sources" [T2-050]. Jeff Miller, "Managing Director, Global Head of Data Platform and Product Engineering at BlackRock" and "a Chief Architect", describes what it replaced: "We sent flat files, we sent large schema definitions, FTP and related transfers, but the Aladdin Data Cloud and Snowflake makes it much simpler for us to get our clients' data and market data from our third-party providers and Aladdin partners back to our clients" [T1-17 Snowflake video, Jeff Miller, undated; Whisper].

Woodhead calls the content "the language of the portfolio", delivered as data products that are "designed, it's thoughtful, it's governed, it's documented, it has metrics around it" [T1-01]. Newman lists what is joining the network: eFront data, Preqin, "firms like London Stock Exchange data", and BlackRock IP "around credit analytics, around mortgage-backed security data, around insurance analytics", "all happening now" [T1-11]. ## 2.7 Developer tools

**AladdinSDK.** The README states the goal: "to make it easier for everyone to efficiently access and utilize Aladdin APIs and Data Cloud" [SDK README]. Installation is `pip install aladdinsdk` on Python 3.9, then optional add-ons such as `asdk_plugin_trading` [SDK README]. The `AladdinAPI` client "wraps over OpenAPI generated python client code based on Aladdin Graph API's swagger specifications" and provides authentication, pydantic validation, response deserialisation, retries, "Rate limiting per API endpoint", error handling and "LRO Utilities to trigger and poll Long Running Operation endpoint calls" [SDK README]. Plugins are built by the `aladdinsdk-plugin-builder` project under github.com/blackrock using openapi-generator v6.6.0, triggered by git tags; the core package reads each plugin's `api_registry.py` and `domain_apis_list.json` to register its APIs, so new add-ons are picked up "without any additional setup steps" [briefing: Studio; SDK README; V8 S59].

Configuration "is performed using Dynaconf" with the environment prefix `ASDK_`, in increasing priority: default file, user file, `ASDK_` environment variables, inline parameters [SDK README]. `RUN_MODE` has three values: "AladdinSDK can run on a developer's local machine or in Aladdin Studio Compute sessions. There is also a test mode used by SDK developers" [SDK README]. In local mode the SDK "uses Keyring internally for secret management" and stores a prompted password in the OS credential manager [SDK README]. A log file per run, retries, pagination options, JSON-to-pandas conversion, Excel export and error emails "while executing their scripts / scheduled jobs" are built in [SDK README; V8 S41, S48, S49].

`ADCClient` "is a wrapper around snowflake-connector-python or snowflake-snowpark-python (connection type is configurable)" and can write a DataFrame to a table [SDK README; V8 S19]. `S3Client` wraps boto3 against "a Storage integration on Studio UI under a personal / shared project" [SDK README]. "DomainSDK Development" lets teams bundle the plugins they need into "business specific SDKs" on top of the core [SDK README].

**URL rewriting and gateways.** "When consuming the Aladdin APIs via an enterprise API management platform such as Azure API Management, the relative URL of the Aladdin APIs are likely to be different (in addition to the host name)", so the SDK accepts `API.URL_REWRITE.FIND` and `REPLACE` settings, a class argument or a per-call argument [SDK README]. The candidate's draft attributes the gateway URL rewriting and an additional-headers feature to two pull requests merged in December 2025 from a janushenderson.com address [REVISED draft Exhibit 33]; the fact-check lists this as not verifiable from the corpus, which holds the README and specs, not the repository history [fact-check A3].

**Studio names in the files.** The README and core specs name Studio UI, Studio Project (OAuth applications and storage sit "under a personal / shared project"), Studio Compute, Studio Notifications, S3 Storage Integration, API Applications, API Token, Studio Space and ADC Admin Center [SDK README; V8 Exhibit 4]. Studio Space appears only in notification settings, as a recipient entity and an event type, and is not defined in the files [V8 S4, S5]. BlackRock marketing calls the hosted environment Aladdin Compute, "a hosted analytics platform with ready-to-use Python environments and automation tools" [briefing: Studio]. The README refers to "'Aladdin Developer' or similar python development environments" where "a kernel restart is always recommended" after config changes [SDK README].

**Developer Portal and the rest.** The APIs page describes a portal with an API catalog, "API framework" documentation on how requests are built, authorised and processed, a Data Dictionary for browsing fields, downloadable Jupyter notebooks and multi-language code samples, all behind a client login; it says there are "dozens of APIs" with new ones added regularly, and it lists Aladdin Data eXchange (ADX) and Aladdin Tools for Excel (ATX) as Studio resources [briefing: Studio, citing the APIs page]. ADX "appears to be bulk data delivery for reconciliation and feeding other systems; ATX is an Excel add-in. Little public detail" [briefing: Studio].
